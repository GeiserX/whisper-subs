### Research synthesis (5/5 agents landed, 2026-07-02)
**Facts (source-verified):**
- FT = Harmony-patched IFileProvider; transforms served files IN-MEMORY (disk untouched, re-read each restart, survives jellyfin-web upgrades). In-memory registrations only → must re-register every boot.
- Integration = REFLECTION ONLY (Jellyfin 10.11 = one AssemblyLoadContext per plugin → no cross-plugin type identity; FT NuGet stale at 1.x/10.10; hard ref would DISABLE our plugin when FT absent). Call `Jellyfin.Plugin.FileTransformation.PluginInterface.RegisterTransformation(JObject)` — payload {id, fileNamePattern:"index.html" (regex), callbackAssembly/Class/Method}. FT then calls OUR `public static string Method(POCO{Contents})` per serve; same-GUID re-registration is idempotent; FT pipeline has NO try/catch (a throw in our callback blanks the whole UI); callback must never return null.
- Production integrators (media-bar 367★, JS-Injector, OpenWatchParty): register from a post-startup hook (IScheduledTask StartupTrigger / StartupService), ALC-scan for the FT assembly, typed POCO callback param (OpenWatchParty's `object`+GetProperty variant is fragile — Newtonsoft deserializes `object` to JObject, CLR GetProperty("contents") misses). Fallback = direct write / feature-off + log.
- FT fragility is REAL: breaks on Jellyfin point releases (Harmony), v2.5.4.0 once crashed whole servers (#46), ARM64 init bug (#64 open), 2.5.11.0 targets 10.11.7–10.11.11 only, single maintainer. Jellyfin core REJECTED native injection (PR #9095) → FT is the ecosystem answer; direct write must remain.
- FT distribution: third-party manifest https://www.iamparadox.dev/jellyfin/plugins/manifest.json; Jellyfin has NO plugin-dependency mechanism → users install FT manually.

**Design decisions (incl. 2 conscious divergences from panel members):**
1. **Coexistence, not one-mode** (diverges from architect's "hosted service picks exactly one mode"): constructor direct-write stays EXACTLY as today (default, most robust); FT registration ADDED whenever FT present (installing FT = the opt-in; no config toggle). Byte-identical tag + idempotent transform ⇒ coexistence is provably safe; writable-root users keep the disk tag as resilience when FT breaks (critic M1 evidence). 
2. **No on-disk tag strip** (diverges from critic C3's cleanup): stripping needs writability (absent in the #108 case), is destructive, and REDUCES robustness. C3's real hazard (double injection) is neutralized by identical marker + AlreadyPresent guard. FT callback = pure self-healing `NormalizeInjection` (strip any whisperSubs tag variants → insert exactly one before </head>; no </head> → return input unchanged; NEVER null/throw) so served HTML is always canonical.
3. Registration from **IHostedService.StartAsync** (via new IPluginServiceRegistrator; critic C1 + architect agree) — fire-and-forget inner task (never delay server start), small bounded retry, records FtPresent/FtVersion/FtRegistered/FtError into Plugin state.
4. **Payload built with FT's OWN JObject type** (reflect RegisterTransformation's param type → static Parse(jsonString) built via System.Text.Json) → no Newtonsoft PackageReference, immune to ALC identity + param-type drift; whole discovery+invoke in try/catch → any failure = keep direct mode, log loudly.
5. **Status panel mode-aware + served-HTML verification** (critic M2): GetInjectionStatus gains Mode + FT fields + best-effort local GET of served index.html grepping the marker (tri-state verified/not/unknown, short timeout, never fails the endpoint; controller-side via IServerApplicationHost). Read-only+FT-absent error message now leads with "install File Transformation (no permission changes)" + keeps chown/chmod + bind-mount alternative. ReinjectScript ALSO re-attempts FT registration (late FT install recovers without restart).
6. Callback = typed POCO `FileTransformationInput{ string? Contents }`; transformation id = our plugin GUID (stable ⇒ idempotent re-register); contract test pins `public static string TransformIndexHtml(FileTransformationInput)` signature.
7. Version → **3.26.0.0** (minor). Env: build/test/gh via machost on the Mac (pod lacks dotnet/gh).
